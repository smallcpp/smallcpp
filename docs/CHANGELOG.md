# Changelog

All notable changes to smallcpp are recorded in this file.

## Unreleased

### Changed

- `split` and `join` return new objects. `split(const char *)` returns a new `StringVec`. Each piece is a new `String *`. The caller receives that pointer. A missing separator returns one copy of the whole string. Consecutive separators yield an empty string. An empty separator or a null separator throws `Exception` with message `string`. `split()` separates on `' '`, `'\n'`, and `'\r'`. Each of those characters is a separator. `join(StringVec *, const char *)` returns a new `String *` and does not clear this string. An empty separator concatenates the pieces. `join(StringVec *)` places one space between pieces. A null source, a null separator, or a null element throws `Exception` with message `string`. `add` and `chars` stay. `string-parts` prints `parts 3 a--b ab a a,,b 3 a,b, b a b 1 hi 1`. `string-space` prints `string-space 3 a b c 3 0 a--b a  b`.
- `Array::address`, `String::at`, and `at` from `VECTOR`, `LIST`, and `TREE` count a negative index from the end. `-1` is the last element. `-2` is the one before it. An index past either end throws `Exception` with message `index`. `from_end` takes a non-negative index. `neg-index` prints `neg-index b a 30 20`.
- An unknown call is no longer rejected while compiling. `missing()` is an external function, and the link fails when that symbol is not defined. `diag_bad-unknown-call` requires the link error.
- The base exception class is `Exception`. The spelling `exception` did not match the class naming rule. Include it as `<exceptions>`. `Exception()` stores a null message. `Exception(const char *)` stores that C string in `message`. The pointer is not copied.
- The preprocessor file and the object file take the input file's base name. `hello.scpp` writes `hello.i` and `hello.o` before the link, for one file and for each file of several. Those names replace `output.i`, `output.o`, and `output.N.o`. `-k` and deletion are unchanged. `-E` and `--emit-llvm` still name their results from the input base name.
- `-o` is optional. One source and no `-o` writes `a.out`. `-k` and `--keep` leave every generated file. Without them, `scpp` deletes the intermediate files after a successful build. `preproc` still deletes nothing. `--emit-llvm` writes LLVM IR for every input and stops before assembling or linking. One input may be named with `-o`, or with a second path ending in `.bc` or `.ll`. Several inputs each use the input base name and `.bc`. `-E` writes preprocessor output for every input and stops. One input may be named with `-o`, or with a second path ending in `.i`. Several inputs each use the input base name and `.i`. `-l` names a library for the link and may be repeated. `-I` and `-L` may be repeated, and one option may list several directories separated by `:`. Those directories are searched in order.
- A program starts at `int main`. The runtime no longer supplies a `main` that calls `answer`. `scpp` reports `program has no main` when an executable's objects do not define `main`. `-c` and `--emit-llvm` still compile one translation unit that does not define `main`. The examples, including `tests/examples/ledger/main.scpp`, define `main`.
- `scpp` compiles and links more than one source file. With `-o`, every positional path is an input. Without `-o`, an executable uses the last positional path as its output and the earlier paths as inputs. Two positional paths and no `-o` are still one input and that executable. Each input writes its base name with `.i` and `.o` before the link, then one Clang link of those objects. `-c` and a path ending in `.bc` still accept one source, because one output file cannot hold several translation units.
- `scpp -g` asks `scpp_cc` to emit LLVM debug info for the source file, line numbers, functions, and types, and the Clang link keeps it. The debug info names the `.scpp` file. Without `-g`, the executable is unchanged. `gdb` or `lldb` can stop in that function and name the source line.
- An environment value that is not a token sequence is not imported. `MAKEFLAGS` from a build is one of those values.
- The driver sources are `src/scpp`. The binary is still `scpp`. `scpp` runs `preproc`, then `scpp_cc`, and then Clang when the result is an executable. It still does not parse, it does not emit LLVM IR, and it does not link the IR library. `preproc` still deletes nothing. `-D` and `-I` are passed only to `preproc`. `-i` and `--ignore-environment` are passed only to `preproc` and import no environment macros. `-o` names the file written by the last phase: the object file with `-c`, the IR file with `--emit-llvm`, and the executable otherwise. A path ending in `.bc` is still LLVM IR. `-c` compiles and assembles and does not link. `-g` is passed to `scpp_cc` and to the Clang link. `-L` is passed to the Clang link as a library search path. `--emit-llvm` asks `scpp_cc` to write LLVM IR and stop before the native link.
- `scpp` coordinates compilation and passes the input and output to `scpp_cc`. It does not parse, it does not emit LLVM IR, and it does not link the IR library. `scpp_cc` is the C frontend. It parses, and it links the C++ IR emitter through `src/emit/emit.h`. `--ast-text FILE` writes a structured text form of the syntax tree. `--ast-dot FILE` writes a Graphviz DOT file. Either file can be requested alone. Both can be requested together with IR emission, through `-o`. `./bin/scpp input.scpp output` still compiles. A normal build writes `scpp` and `scpp_cc`.
- A normal build also writes `preproc`.
- Test programs stay out of a normal build. `cmake --build build` writes `scpp`, `scpp_cc`, `preproc`, and the libraries. `command_line_test`, `parse_test`, and `verify_module` are built when the `test` target is requested. That target builds the ordinary targets, then CTest builds those three programs and runs the suite.
- The compiler target and binary are `scpp`. `./bin/scpp input.scpp output` compiles the same way `shell` did. `scpp -o output input.scpp`, `--help`, and `--version` are the same. `--version` prints `scpp: v0.1`. The driver sources are `src/scpp`.
- The shell code generator is split by phase. `src/shell/codegen.cpp` drives lowering. Types and scalars, calls, aggregates, namespaces, classes, allocation, exceptions, and print and format each have their own file: `lower_scalar.cpp`, `lower_call.cpp`, `lower_aggregate.cpp`, `lower_namespace.cpp`, `lower_class.cpp`, `lower_alloc.cpp`, `lower_except.cpp`, and `lower_print.cpp`. `src/shell/lower.hpp` holds the types those files share. Lowering behavior is unchanged.

### Fixed

- A pure virtual method declared in a header is linked once when more than one translation unit includes that header. `Database` relies on this.
- `scpp` joins the stack maps when a link contains more than one smallcpp object. The collector then traces a safepoint in a later object, including `new` inside a constructor in a library. `sqlite-round` relies on this.
- A call through a function pointer in an array, written `fns[i](args)`, was rejected. The call runs the function stored at that index.
- A call inside `try` did not unwind. An exception thrown from the called function was not caught. That call now unwinds to the handler.
- A destructor could not take parameters. `~Class(int n = extra())` is a destructor. `pointer->~Class()` and `pointer->~Class(5)` call it. An omitted argument is evaluated at the call. A passed argument is not. The collector calls the destructor with the object only, and that call uses the omitted defaults.
- A `new` inside a called function keeps pointers that the caller saved on its stack. The stack map covers the function that calls the allocator. A constructor or edit that allocates while it still needs an argument now keeps that argument alive. `string-edit` relies on this.
- Merging the syntax tree into the error-recovery grammar dropped `%locations` and `%define parse.error custom` while leaving `yyreport_syntax_error` and the scanner's column tracking in place. The generated parser did not compile, so `cmake --build` stopped before the build finished. Those directives are restored, and `docs/smallcpp.y` and `docs/smallcpp.l` match `src/compiler` again.

### Removed

- `super`. It is not a keyword. A base method is `Base::method()`, or `method()` when that name is not hidden. `this` remains a keyword. `tests/examples/super.scpp` and its CTest entry are removed.
- Compound literals. `(type){ ... }` does not parse, including `(int[]){1, 2}`. `tests/examples/compound-literal.scpp` and its CTest entry are removed. `print` and `format` are unchanged.

The shell is the first caller. `shell input.scpp output` still compiles. `shell -o output input.scpp` does the same. `--help` and `--version` print and exit. An unknown option exits with status 2. The preprocessor is not started.
- A syntax or semantic error prints the file, line, and column, the source line, and a short message. A syntax error also names the tokens that were expected. There is no caret under the line. `bad-verbose-syntax` fails unless the diagnostic contains `int x = ;` and `expected IDENTIFIER`. `bad-verbose-semantic` fails unless the diagnostic contains `return missing;`.
- A base may be virtual. Two paths to that base share one subobject, and construction and member access use that subobject. A virtual method may be pure, written `= 0`. A class with a pure virtual method is abstract, and creating an instance, including with `new`, is rejected. A derived class that implements the method can be created, and a call through a base pointer reaches that implementation. A destructor may be virtual. `delete` of a base pointer calls the derived destructor. It still type-checks, does not deallocate, and runs once. The collector calls that same destructor when it reclaims an object whose destructor has not run. `exec-virtual-base` returns 5. `exec-pure-virtual` returns 8. `exec-virtual-dtor` returns 3. `exec-virtual-collect` returns 9.
- A virtual method is dispatched through a vtable with the same boundaries as C++. An override replaces the base slot, including an override that does not repeat `virtual`. A call through a base pointer loads that base subobject's vtable. The first polymorphic base shares the leading vtable pointer. Each other polymorphic base keeps its own, and a slot there adjusts `this` back to the class that defines the final overrider. `Base::method` stays a direct call. `exec-virtual` returns 4. `exec-override` returns 6. `exec-base-virtual` returns 7. `exec-multi-virtual` returns 7. Ref-qualifiers, virtual templates, and covariant reference returns are excluded with the rest of those features. A covariant pointer return is not accepted; the return type must match.
- A destructor runs in three ways. A direct call is `object.~Class()` or `pointer->~Class()`. `delete` type-checks the pointer and calls the destructor. It does not deallocate. After `delete`, the collector does not call that destructor again. When the collector reclaims an object whose destructor has not run, the collector calls it. Reclaim order is not a sequence the program can rely on. If destructors must run in a known order, the program calls them directly or with `delete`. `exec-dtor-call` returns 4. `exec-delete-dtor` returns 5. `exec-collect-dtor` returns 8.
- `throw` and `catch` run with the Clang personality. A thrown value is allocated by `__cxa_allocate_exception` and thrown with a type info the personality can match. A typed `catch` reads the value. `catch (...)` enters and leaves the runtime handler, so it does not crash. A bare `throw` is `__cxa_rethrow`. The programs are `exec-catch`, `exec-catch-all`, and `exec-rethrow`.
- The suite runs a short program for each feature the shell can execute, and checks the exit status or the printed text. Features that cannot run yet still have a bitcode check. Bad snippets are separate examples. Each one must make the compiler exit non-zero, and the diagnostic must name the problem. A syntax error that recovers is reported twice.
- The precise collector implements `smallcpp_alloc` and traces the stack maps at safepoints. `delete` stays a no-op. `tests/examples/live-root.scpp` allocates with `new`, keeps that pointer live across a second `new`, and `collect_live_root` fails unless the collector sees it.
- The shell writes an executable when the output path does not end in `.bc`. It compiles the verified module and links the Clang runtime, the collector, and the bodies of `smallcpp_print` and `smallcpp_format`. `run_return` runs `return-zero` and requires exit status 0. `run_print` runs `print-literal` and requires the text `count is 1` followed by a newline. `run_format` runs `format-value` and requires exit status 0, which is the byte after the formatted `4`.
- The shell lowers `print` and `format`. Each call goes to a declared runtime function with no body, `smallcpp_print` or `smallcpp_format`. A literal format string is still checked. `format` returns a pointer, and that pointer is in the stack map at the call. The examples are `print-literal` and `format-literal`. The C runtime is not implemented. The earlier compile tests still pass.
- The shell lowers exceptions. `throw` of an expression, a bare `throw`, `try`, a typed `catch`, and `catch (...)` each have a short example. A guarded region is an `invoke`. A handler is a landing pad, and `catch (...)` is the catch-all clause. The personality is `__gxx_personality_v0`, declared with no body. The examples are `throw-value`, `rethrow`, `catch-typed`, and `catch-all-handler`. `print` and `format` stay later. The earlier compile tests still pass.
- The shell lowers `new` and `delete`. `new` of an object, an array, and a pointer calls the declared allocator `smallcpp_alloc` and runs a constructor when the type has one. The array form passes the bound. `nullptr` and `NULL` are the null pointer. `delete` evaluates its operand and emits no deallocation and no destructor call. Each allocation is a safepoint, and the stack map includes the pointer just returned. The examples are `new-object`, `new-array-call`, `new-pointer`, `delete-ptr`, and `nullptr`. The collector is not implemented. Exceptions, `print`, and `format` stay later. The earlier compile tests still pass.
- The shell lowers classes. A class is an object type, a base is a subobject, and `this` is a pointer. A const method takes a pointer to const. Constructors, destructors, and initializer lists are functions. `Base::method` and an unhidden name are direct calls. A virtual method is an indirect call through one pointer in the object. Access is a compile-time check. The examples are `method`, `const-method-call`, `ctor`, `dtor`, `init-list`, `two-bases`, `virtual-call`, and `base-call`. `delete` does not call a destructor yet. Allocation, exceptions, `print`, and `format` stay later. The earlier compile tests still pass.
- The shell lowers namespaces. `namespace name { }`, a qualified name, `using name;`, and `using namespace name;` each have a short example and a CTest. Lookup changes. A namespace is not a runtime value. The examples are `namespace-fn`, `qualified-call`, `using-name`, and `using-namespace`. Classes, allocation, exceptions, `print`, and `format` stay later. The earlier compile tests still pass.
- The shell lowers aggregates. A struct, a union, an enum, an array, a pointer, empty `[]` on a parameter, a bit-field, a designated initializer, and a brace initializer each have a short example and a CTest. A named bit-field is a field of that width. Empty `[]` on a parameter is a pointer. An enum constant is an integer. The examples are `struct`, `union`, `enum`, `array`, `pointer`, `array-param`, `bitfield`, `designated-init`, and `brace`. Classes, allocation, exceptions, `print`, and `format` stay later. The earlier compile tests still pass.
- The shell lowers calls. A direct call, an overload, a default argument, a varargs function, `static`, `extern`, `inline`, `typedef`, `register`, and a string literal each have a short example and a CTest. Two functions that share a name and differ in their parameters become two LLVM functions, and the call selects one. A default is passed at the call. `static` is internal linkage. `extern` is a declaration. `inline` marks the function inline. `typedef` is a compile-time alias and adds no value. `register` adds no instruction. A string literal is a private constant. The examples are `call`, `overload-call`, `default-call`, `varargs`, `static`, `extern`, `inline`, `typedef`, `string`, and `register`. Aggregates, namespaces, classes, `print`, and `format` stay later. The earlier compile tests still pass.
- The shell lowers scalar functions to an LLVM module. Types are `void`, `bool`, `char`, `short`, `int`, `long`, `float`, `double`, `signed`, and `unsigned`, including `(void)` and empty `()`. A function may have parameters, locals, and file-scope scalars, numeric literals, `true` and `false`, the operators and assignments in the grammar, casts, `sizeof`, the comma operator, and the conditional operator. Postfix `++` and `--` are recorded separately from the prefix operators. `if` / `else`, `switch` / `case` / `default`, `while`, `do`, `for` (including a declaration in the first clause), `break`, `continue`, `goto`, and labels lower to branches. `const` and `volatile` are qualifiers; a volatile object is a volatile load or store. Calls, aggregates, namespaces, and classes are left for later. The IR is not printed as text, and no executable is linked. Each of those features has a short example under `tests/examples` and its own CTest. The verifier loads that example's bitcode, runs `verifyModule`, and checks that one feature. The examples are `if`, `else`, `while`, `do`, `for`, `for-decl`, `switch`, `break`, `continue`, `goto`, `void`, `bool-type`, `char`, `short`, `long`, `float`, `double`, `signed`, `unsigned`, `empty-list`, `parameter`, `local`, `global`, `const-var`, `volatile`, `true`, `false`, `literal`, `cast`, `sizeof`, `comma`, `conditional`, `add`, `sub`, `mul`, `div`, `mod`, `shift`, `compare`, `bit-and`, `bit-or`, `bit-xor`, `complement`, `negate`, `not`, `logical-and`, `logical-or`, `assign`, `add-assign`, `post-inc`, and `pre-inc`. `compile_return` still checks `tests/examples/return-zero.scpp`.
- The shell lowers one function from the syntax tree to an LLVM module. `tests/examples/return-zero.scpp` is `int answer(void) { return 0; }`. The module is verified and written as bitcode. The IR is not printed as text, and no executable is linked. `print` and `format` stay builtins for a later C runtime. CTest `compile_return` fails if the module does not verify.
- A method may be `const`, written after its parameter list. `new` allocates an array or a pointer type. `bool`, `true`, and `false` are keywords. A struct or union member may be a named bit-field. Initializers may use `.member = value`, `[index] = value`, and a brace list for a struct or an array. `()` is an empty parameter list and means no parameters. `(void)` still parses. Templates, lambdas, `auto` as a type, references, ref-qualifiers, operator overloads, anonymous namespaces, and compound literals stay unsupported. `tests/examples/const-method.scpp`, `tests/examples/new-array.scpp`, `tests/examples/bool.scpp`, `tests/examples/bit-field.scpp`, `tests/examples/designated.scpp`, `tests/examples/empty-params.scpp`, and `tests/examples/brace-init.scpp` are registered with CTest. `nullptr` and `NULL` are already the same kind of node in `tests/examples/null.scpp`. `delete` of a pointer and a failing `delete` of a non-pointer are already covered by `tests/examples/delete.scpp` and `tests/examples/reject-delete.scpp`.
- Constructors and destructors are class methods with no return type. A constructor is named for its class. A destructor is `~ClassName()`. A constructor may have an initializer list, `ClassName(args) : member(expr), base(expr) { ... }`, and that list may initialize more than one base. A class may list more than one base. A parameter may be written `name = expression`. `using name;` and `using namespace name;` are supported. Anonymous namespaces are not. Two functions may share a name when their parameter lists differ. Operator overloading is not supported. `super` is not a keyword. A base method is `Base::method()`, or `method()` when that name is not hidden. `this` remains a keyword. `tests/examples/ctor-dtor.scpp`, `tests/examples/default-arg.scpp`, `tests/examples/using.scpp`, `tests/examples/overload.scpp`, and `tests/examples/multi-base.scpp` are registered with CTest.
- `nullptr` and `NULL` are keywords for the same null pointer constant. They produce the same kind of syntax-tree node. A `new`-expression creates a pointer. `delete` is a keyword and a no-op, because collection is precise, and its operand is type-checked as a pointer. `tests/examples/null.scpp`, `tests/examples/delete.scpp`, and `tests/examples/reject-delete.scpp` are registered with CTest.
- `catch (...)` catches every exception type. The `...` is not a parameter and is not the variadic-parameter node. A `catch` with a parameter still parses. `tests/examples/catch-all.scpp` is registered with CTest.
- Parser examples cover a namespace, a class with one base and a method, `try`/`catch`/`throw`, a variadic parameter, and native `print`/`format`. `parse_test` fails when an example's expected syntax-tree nodes are missing. `tests/examples/tree-shape.scpp` checks the shape of the tree. Each example is registered with CTest.
- `print` and `format` are native. A call takes a string literal in C++23 format-string syntax, then the arguments that fill its replacement fields. `print` writes the formatted text. `format` produces the formatted string. They are not declarations the program supplies, and they are not the C++ standard library. The syntax tree records them as `print` and `format` nodes. `tests/examples/print-format.scpp` is registered with CTest.
- The parser builds a syntax tree. Node kinds are defined in `src/compiler/ast.h` and constructed in `src/compiler/ast.c`. The grammar actions in `src/compiler/smallcpp.y` cover translation units, namespaces, classes, methods, statements, try/catch/throw, and new. The parser actions do not generate code.
- CTest runs `accept.scpp`. That test must build the syntax tree and pass.
- CTest runs the parser examples. `accept.scpp` must pass, and each reject example must fail. New parser checks are registered in `tests/CMakeLists.txt`.
- `docs/smallcpp.y` is a copy of `src/compiler/smallcpp.y`, not a symbolic link. `docs/smallcpp.l` is a copy of `src/compiler/smallcpp.l`. The sources in `src/compiler` stay in place.
- Scanner and parser diagnostics include the file, line, and column.
- After a syntax error, the parser resynchronizes at a semicolon and continues. An invalid character is reported and skipped, so one file can report more than one error.
- `tests/examples/reject-errors.scpp` contains several errors.
